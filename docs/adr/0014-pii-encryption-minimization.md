# 0014. 個人情報は暗号化し、持たなくてよいものは持たない

- 状態: 承認
- 日付: 2026-10-25
- 関連: [design.md](../design.md) 9.5, 9.6, 4.10

## 背景

DB が漏洩しても個人情報が読めないようにしたい。さらに、できるだけ個人情報を持ちたくない。退会したユーザーの情報は、改ざん検知のための監査ログを壊さずに消したい。

## 決定

- 個人情報はアプリ側で AES-256-GCM で暗号化し、検索はブラインドインデックス（HMAC）で行う。常に有効
- ユーザーごとのデータ鍵を使い、削除時に鍵を消して読めなくする（crypto-shredding）
- 表示名・プロフィール・OAuth のメールなどは既定で持たない
- メールアドレスはブラインドインデックスのみを持つ最小化モードを選べる
- データの種類ごとに保持期間を設け、IP アドレスなどは期間後に切り詰める

## 結果

- 部分一致の検索はできない
- KeyStore の鍵を失うとデータを復元できない
- 最小化モードでは IAM から非同期の通知ができない（宛先はホスト先が解決する）

## 検討した代替案

- DB の暗号化機能に任せる（DB の管理者や漏洩したバックアップからは読める）
