# 0079. Group のネストは同じ範囲に限り、含む Group の一覧を管理の操作で計算する

- 状態: 承認
- 日付: 2026-10-27
- 関連: [design.md](../design.md) 3.2、4.5、11.5、[0064](0064-authz-check.md)、[0078](0078-org-hierarchy.md)

## 背景

部署とチームのように、Group を Group に入れたい。design.md 11.5 は「Group のネストは推移閉包を書き込み時に計算する。
深さの上限と循環の禁止」とする。M4 の Group の所属はユーザーとサービスアカウントだけだった。

## 決定

- フィーチャー `nested_groups`（依存なし。realm の Group と Org の Group の両方）。Group の所属に `principal_type: group` で
  Group を入れられる。入れる Group は同じ範囲（realm の Group なら realm の Group、Org の Group なら同じ Org の Group）だけ
  （ほかは `400 invalid_principal`）
- 入れた Group の所属（ユーザー・サービスアカウント）に、含む Group の付与が効く。Org の Group の付与は、これまでどおり
  その Org の使える所属を持つ間だけ
- 循環（自分自身・自分が含む Group に入る）は `409 group_cycle`。入れ子は、いちばん外の Group を含めて 5 段まで
  （`409 group_too_deep`）。いくつもの Group に入ってよい（木でなく有向非巡回グラフ）
- 閉包テーブル `authz_group_closure`（Group と、それを含む Group と、最も長い経路の段数）。Group としての所属を変えたとき・
  Group を消したときに、管理の操作（authz/manage）が、所属を変えた Group とそれが含む Group の行を、Group としての所属から
  計算し直す。アダプタは行の読み書きだけ
- 判定（authz/check）は、フィーチャーが有効なときだけ、1回の問い合わせで、所属する Group とそれを含む Group の付与を集める
- Group を入れるにも、入れ先の Group の付与の権限をすべて持っていることを求める（権限の引き上げを防ぐ。M4 と同じ）
- フィーチャーを無効にするときは、閉包の行から消し、その後に Group としての所属を消す。Group と、ユーザー・サービスアカウントの
  所属は残す。無効にする途中でも Group としての所属は外せる

## 理由

- 判定は書き込みよりずっと多い。閉包テーブルなら判定のたびの展開が1回の問い合わせになる
- 計算を管理の操作に置けば、アダプタごとに同じ計算を持たずに済む（どれも同じ行を置く）。Org 階層（ADR 0078）は木なので
  アダプタで差し替えたが、Group は複数の親を持てるので、差分の更新より計算し直しのほうが誤りにくい。段数の上限で量は限られる
- 範囲を混ぜない：realm の Group を Org の Group に入れると、Org の外の人に Org の権限が効く。同じ Org に限れば、Org の Group の
  「その Org の使える所属を持つ間だけ効く」がそのまま成り立つ
- 閉包の行から消せば、片付けを始めた時点で含む Group の付与が効かなくなる

## 影響

- Group の所属の一覧に `principal_type: group` が出る
- 深い・広い入れ子では、所属の変更で計算し直す量が増える（段数の上限で抑える）

## 検討した代替案

- 判定のたびに所属をたどる：判定のたびに段数分の問い合わせ（キャッシュに外れたとき）
- アダプタで差分を更新する：複数の親があると、外したときに別の経路が残るかの判定が要り、アダプタごとに持つことになる
- realm の Group を Org の Group に入れられるようにする：Org の範囲の付与が Org の外に漏れる
