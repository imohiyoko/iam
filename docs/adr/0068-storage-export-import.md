# 0068. Storage の書き出しと読み込み（移行）は表ごとの行を JSON Lines で運ぶ

- 状態: 承認
- 日付: 2026-10-27
- 関連: [design.md](../design.md) 2.4、[0067](0067-postgres-adapter.md)

## 背景

単一インスタンスの SQLite から PostgreSQL へ移る手段が要る（roadmap M6）。ポートの Repository ごとに全件を読む口を
足すと、表が増えるたびに書き出しの漏れが起こりうる。

## 決定

- `iam storage export -config … -out dump.jsonl` と `iam storage import -config … -in dump.jsonl`
- SQL のアダプタ（SQLite・PostgreSQL）は `port.Dumper` を持つ。2つは同じスキーマ（0067）なので、表ごとの行をそのまま運ぶ
  （`shared/sqldump`）。インメモリのアダプタは持たない
- 形式は JSON Lines。1行目はヘッダー（形式の版と、表と列の一覧）、続く各行は表の名前と値（null・整数・文字列・バイト列）。
  PostgreSQL の outbox の `ord` は運ばず、追加の順で書き出して読み込みの順で振り直す
- 書き出しは一貫した時点（SQLite は BEGIN IMMEDIATE、PostgreSQL は advisory lock のトランザクション）。読み込み先は
  マイグレーション済みで空でなければならず、表と列が書き出し元と同じであることを確かめ、全部を1つのトランザクションで入れる。
  入れた後に監査ログのチェーンを検証する
- ファイルは 0600 で、既にあれば上書きしない。暗号化した個人情報とハッシュを含むが、KeyStore の鍵は含まない
  （移行先でも同じ鍵を使う）

## 理由

- 表の一覧をスキーマから読むので、表を足しても書き出しに漏れが無い
- 同じ版どうしだけで運ぶ（表と列の一致を確かめる）ので、変換の規則を持たずに済む

## 影響

- 書き出し元と読み込み先は同じ版の IAM でなければならない（版を上げるのは移行の前か後）
- 書き出しの間は書き込みが止まる（一貫性のため）。大きな DB では停止の時間を取って行う
- EphemeralStore（セッションのキャッシュ・認可要求など）は運ばない。移行の後、進行中のログインはやり直しになる
