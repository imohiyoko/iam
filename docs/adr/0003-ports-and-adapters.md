# 0003. 外部依存をポート & アダプタで切り離し、必須の製品を持たない

- 状態: 承認
- 日付: 2026-10-25
- 関連: [design.md](../design.md) 2.4

## 背景

当初は PostgreSQL と Redis を必須にする案だったが、セルフホストする利用者の環境はさまざまで、特定の製品を必須にすると導入の障壁になる。メール送信などもホスト先の事情に任せたい。

## 決定

- DB、キャッシュ、通知、鍵管理、イベント出力、時刻取得をポート（Go のインターフェース）として定義し、実装はアダプタとして外に置く
- 唯一の必須ポートは Storage。SQLite + インメモリなら外部サーバーなしで起動できる
- コアはアダプタを import しない（依存は常にアダプタ → コア）

## 結果

- どの環境でも小さく始められる
- ポートの設計を誤るとアダプタ全体に影響するため、インターフェースを慎重に決める必要がある
- 複数インスタンス構成では共有できるアダプタ（Redis 等）が必要になる。起動時の構成チェックで検出する

## 検討した代替案

- PostgreSQL と Redis を必須にする（初期案。導入の障壁が高い）
