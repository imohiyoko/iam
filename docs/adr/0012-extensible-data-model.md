# 0012. データモデルは最初から拡張可能な形にする

- 状態: 承認
- 日付: 2026-10-25
- 関連: [design.md](../design.md) 3, 4.5, 11

## 背景

realm（ユーザープール）、人間以外の主体、Org 管理ユーザー、リソース単位の権限などを後から足すと、全テーブルの移行が必要になる。

## 決定

- 全テーブルに realm_id を持たせる
- 認可の主体を principal（user / service_account / group）として抽象化する
- ユーザーに所有者（個人 / Org）を持たせる
- ロール付与にリソースの範囲を持たせ、認可判定は `check(principal, action, resource, context)` に統一する
- 機能をオフにしても、スキーマは同じで既定値が入るだけにする

## 結果

- 後から機能を有効にしても移行が要らない
- 使わない列のわずかなコスト（インデックスの先頭の固定値など）を受け入れる

## 検討した代替案

- 必要になった時点でスキーマを拡張する（移行コストが大きい）
