# 0036. Membership ごとにメールアドレスを結び付け、ログインの手がかりで Org を選ぶ

- 状態: 承認
- 日付: 2026-10-25
- 関連: [design.md](../design.md) 4.4

## 背景

仕事用と個人用のように、メールアドレスごとに使う Org を分けたい。Org 側も、招待に使ったアドレスでそのユーザーを扱いたい。また当初の目標として、ログインに使った手段（passkey、IP など）で入る Org を切り替えたい。

## 決定

- Membership ごとに、その Org で使う確認済みのメールアドレスを1つ結び付けられる（未設定なら primary）
  - 招待では、招待したアドレスがそのまま結び付く（受け入れ時に所有確認が必要）
  - 本人も設定・切り替えができる。Org のポリシーで、所有ドメインのアドレスに限定したり切り替えを禁止したりできる
- Org とその文脈の連携先から見えるのは、結び付けたアドレスだけにする（ID トークンの `email`、通知の宛先）
- ログイン時の Org の選択に、ログインに使った手がかり（メールアドレス、OAuth のアカウント、passkey の既定 Org、IP）を使う。優先順は、明示的な指定 → 手がかり → 前回の Org → 個人 Org
- 手がかりは選択の優先度にすぎず、入れるかどうかはポリシーで決まる

## 結果

- 同じアカウントのまま、アドレスや認証手段ごとに Org を自然に切り替えられる
- Org にほかのメールアドレスを見せずに済む（プライバシーの向上）
- 結び付いたアドレスの削除には、結び付け直しが必要になる

## 検討した代替案

- Org ごとに別アカウントを作る（アカウントが分散し、0001 の多対多の目標に反する）
- 全メールアドレスを全 Org に見せる（プライバシー上の問題）
