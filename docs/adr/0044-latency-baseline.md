# 0044. 主要操作のレイテンシの基準値と、CI での計測

- 状態: 承認
- 日付: 2026-10-25
- 関連: [design.md](../design.md) 2.6、5.3、12、roadmap M0

## 背景

M0 で、主要操作（セッション検証、認可判定に使うクエリ）のベンチマークと、レイテンシの基準値を決めることになっている。M0 の時点ではセッションも認可判定もまだ無いため、それらを構成する処理を計測して基準値を置き、M1・M4 で実際の操作のベンチマークに置き換える。

## 計測（4 コアの開発環境、Go 1.27.0。中央値）

| ベンチマーク | 何の目安か | 計測値 |
|---|---|---|
| `BenchmarkGetHit`（EphemeralStore インメモリ） | セッションの有効性のキャッシュに当たった検証（5.3） | 約 0.25µs |
| `BenchmarkDecrypt`（shared/pii） | 個人情報1件の復号（データ鍵の取り出しを含む） | 約 2.7µs |
| `BenchmarkEmailIndex`（shared/pii） | ブラインドインデックス1件 | 約 2.3µs |
| `BenchmarkPointLookup`（SQLite） | キャッシュに外れたときの ID での1件取得（1トランザクション） | 約 45µs |
| `BenchmarkAuditRecord`（SQLite） | 監査ログ1件の追記（ハッシュチェーン + outbox） | 約 0.7ms（`synchronous(FULL)`。コミットごとに fsync する） |

## 決定

| 操作 | 基準値（目標） | CI の上限 |
|---|---|---|
| キャッシュに当たったセッション検証 | 1µs | 2µs |
| 個人情報1件の復号 | 10µs | 20µs |
| ブラインドインデックス1件 | 10µs | 20µs |
| キャッシュに外れたときの1件取得（SQLite） | 200µs | 500µs |
| 監査ログ1件の追記（SQLite） | 1ms | 3ms |

- 上限は `bench/baseline.txt` に置き、CI の `bench` ジョブが `-count 5` の中央値と比べて、超えたら失敗する（`scripts/benchcheck.sh`）
- CI の上限は、共有の実行環境のぶれを見込んで基準値より緩くする。基準値そのものは、性能の劣化に気づくための目標として扱う
- M1 でセッション検証（キャッシュあり・なし）、M4 で `check` のベンチマークを足し、この表の代わりの行を置き換える。M4 の完了条件「`check` のレイテンシが M0 で決めた基準を満たす」は、キャッシュに当たれば 1µs 台、外れても 200µs 以内を目安にする

## 結果

- 性能の劣化を PR の時点で検出できる
- 共有の CI 環境では計測値がぶれるため、上限に余裕を持たせており、小さな劣化は見逃しうる

## 検討した代替案

- 計測だけして比較しない：劣化に気づけない
- 前回の結果との相対比較（benchstat）：CI の環境のぶれで誤検知が多い。必要になれば追加する
