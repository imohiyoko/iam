# 0101. TOTP とパスワードを認証方式のポートに載せ、方式専用の表から authn_credentials へ起動時に移す

- 状態: 承認
- 日付: 2026-11-02
- 関連: [design.md](../design.md) 3.1、4.1、4.6、5.2、11.12、[0011](0011-build-time-features.md)、[0050](0050-second-factor.md)、
  [0051](0051-password.md)、[0067](0067-postgres-adapter.md)、[0068](0068-storage-export-import.md)、[0073](0073-build-and-feature-toggle.md)、[0082](0082-account-merge.md)、
  [0090](0090-authenticator-plugins.md)、[0092](0092-authenticator-port-implementation.md)、[0093](0093-acr-aal-step-up.md)

## 背景

0092 は認証方式のポート `Authenticator` と汎用の認証情報 `authn_credentials` を作り、HOTP を最初の方式にした。既存の
passkey・TOTP・パスワードは 1 方式ずつ移すと決めた。この ADR では TOTP とパスワードを移す（passkey は別の PR）。

移すに当たって、次を決める必要がある。

- TOTP はフィーチャーでなく、いつも動く（コアの方式）。0092 の方式はフィーチャーに属する
- パスワードは、メールアドレスで本人を引き当てる。ポートの方式は Storage を触れず、1要素目の始めには本人が分からない
- パスワードのハッシュ（argon2id）は 1 回で数十ミリ秒かかる。Storage のトランザクションは直列（SQLite の BEGIN IMMEDIATE、PostgreSQL の advisory lock。0067）なので、
  その中でハッシュを計算すると、ほかの書き込みがすべて待つ
- 方式専用の表の秘密は、AAD の違う暗号文（`totp.secret`）か平文のハッシュで、SQL のマイグレーションでは `authn_credentials`
  （AAD は `authn.credential.<方式>.<ID>`）の形に写せない
- 移した後のデータを、移す前のバイナリが読まないようにする（0092：台帳で突き合わせる）
- 方式専用のパスの互換、AAL・amr・acr（0093）を変えないこと

## 決定

### 方式

- `authn/method/totp`（方式 `totp`）：所持の要素、`amr` は `otp`、AAL の上限は 2、2要素目だけ。データは秘密と最後に使った
  時間窓。照合は前後 1 窓で、使った窓は比較と交換で書く（同時の使用・再使用は通らない）。1人に1つ（`409 totp_exists`）
- `authn/method/password`（方式 `password`、フィーチャー `password`）：知識の要素、`amr` は `pwd`、AAL の上限は 1、1要素目だけ。
  データは argon2id のハッシュ。規則（長さ・NFKC・漏洩の確認・ハッシュのパラメータの更新）は 0051 のまま方式に移す
- TOTP はコアの方式にする。`MethodInfo.Feature` を空にでき、空の方式はコアが組み込みとして `method.Active` に渡す（フィーチャーを
  問わずに動く）。`method.Register`（フィーチャーのプラグイン）では空にできない
- パスワードの方式は `features/password` が登録し、フィーチャーが動いていれば、コアが設定（ハッシュのパラメータ、最低長、漏洩の確認）を
  入れたものに置き換える

### ポートに足すもの

- `MethodEnv.Users`（`LoginUser`）：ログイン ID で本人を決める方式に、コアが渡す本人の引き当て。確認済みのメールの、ログインできる
  ユーザーだけを返し、それ以外は理由を区別せず `NotFound`。ログイン ID ごと・接続元ごとの回数の上限（`per_account`）をここで数える。
  方式は、本人が無いときも同じ重さの照合をしてから失敗する
- `MethodResult.KnowledgeBreached`：知識の要素が漏洩済みか（警告の評価。0051 のまま）
- `MethodEnv.RecentAuth` と、復旧専用のセッションでの登録の `Usage = recovery`：パスワードの初めての設定は直近の認証を求め、
  置き換えは今のパスワードを求め、復旧では求めない（0051 のまま）
- `CredentialStore.Revoke`：方式が自分の認証情報を置き換える（パスワードの変更）。読んだ後に変わっていれば `Conflict`

### 重い計算をトランザクションの外で行う

- コアは、ログイン（`Complete`）と登録の始め（`EnrollBegin`）を、トランザクションの外で呼ぶ。そのとき方式に渡す
  `CredentialStore` は、操作ごとに短いトランザクションで動く。書き込みは今までどおり比較と交換なので、操作の間の変更は `Conflict`
- コアは、方式が返した認証情報をセッションの発行のトランザクションで読み直し、無効化されていないことに加えて、暗号文が方式の確かめた
  ときと同じことを確かめる（その間の変更・無効化を拒む）
- パスワードの設定は、始めで長さ・漏洩・今のパスワードを確かめてハッシュを作り（封をしたフローの状態に入れる）、完了で古いものを
  無効化して作る。始めと完了の間に変わっていれば `409 password_changed`。登録の完了は今までどおり呼び出し側のトランザクションで行う
- 知識の要素は、登録の始めで今の秘密を照合するので、本人ごとの回数の上限（`per_account`）を始めで数える（完了では数えない）

### セッション

- ログイン ID で本人を決めた方式（パスワード）のセッションは、今までどおり引き当てたメールに結び付け、認証情報には結び付けない。
  パスワードの置き換え・削除・汎用のパスでの無効化は、今のセッション以外をまとめて失効させる（5.2）。その他の方式は、使った認証情報に
  結び付ける（0092 のまま）
- 知識の要素の登録（復旧専用のセッションを除く）と、本人による無効化で、今のセッション以外を失効させる（パスワードの今の動作と同じ）
- AAL・amr・acr は変えない。`amr` は TOTP が `otp`（2要素目では `mfa` を足す）、パスワードが `pwd` で、0093 の対応表で求める

### 移行

- 方式専用の表（`authn_totp_credentials`・`authn_password_credentials`）の行は、起動のたびに `authn_credentials` へ移す
  （`credential.MigrateLegacy`）。1 行ずつ、新しい行を作って古い行を消すのを同じトランザクションで行うので、途中で止まっても
  続きから進む。無効化したものも移す（履歴）
  - TOTP は内部 ID と公開 ID（`otp_…`）を保つ。セッションの結び付き（0092 の `crd_…` と同じく検証で確かめる）と、
    方式専用のパス・運営者の無効化の ID がそのまま効く。秘密はユーザーのデータ鍵で復号し、方式のデータとして暗号化し直す
  - パスワードは内部 ID（`pwd_…`）を保ち、公開 ID（`crd_…`）を新しく作る（前は公開 ID が無かった）
  - 秘密を戻せなければ（データ鍵が無いなど）、移さずに起動を止める（fail-closed）。古い行は残る
- SQL のマイグレーションは足さない（表の形は変えない。古い表は、次のリリースで消す）。Storage には、古い表の全 realm の列挙
  （`ListAll`）と削除（`Delete`）だけを足す
- 移したことは台帳（0011、0073）に `migration:authn_credentials_totp_password` として記録する。フィーチャーに属さないコアのデータの
  移行は、名前を `migration:` で始め、`feature.RegisterMigration` で知っていると宣言したバイナリだけが突き合わせから外す。移す前の
  バイナリは、この記録を「バイナリに無いフィーチャー」として起動を拒む。知らない `migration:` の記録（より新しいバイナリの移行）
  も拒む。`iam features plan` は移行の記録を見ない（同じ版のソースから作るバイナリは、どの構成でも移行を行う）
- 0092 の「読みは新しい表を先に、無ければ古い表」は行わない。起動で移し終えてから要求を受けるので、読みは新しい表だけでよい。
  そのかわり、移す前のサーバーを止めてから移した後のサーバーを起動する（台帳が、移す前のサーバーの再起動を拒む）。止め切る前に
  移す前のサーバーが書いた行は、次の起動で移る
- 戻すときは、移す前に `iam storage export` で書き出したものを `iam storage import` で読み込む（0068）。移した後の登録・変更は、
  戻した先では失われる

### HTTP

- 汎用のパス（0092）で TOTP とパスワードを使える。`/v1/login/methods/password:begin`・`:complete`（payload は `email`・`password`）、
  `/v1/login/second-factor/totp:begin`・`:complete`（`code`）、`/v1/me/credentials/{totp|password}:enroll-begin`・`:enroll-complete`、
  `/v1/me/credentials/{id}:revoke`。登録の始めに `429` を足す（知識の要素の回数の上限）
- 方式専用のパス（`/v1/login/password`、`/v1/login/second-factor:verify` の `totp_code`、`/v1/me/totp:start`・`:confirm`、
  `/v1/me/totp/{id}:revoke`、`/v1/me/password:set`・`:remove`）は残し、中で同じ方式とコアのサービスを呼ぶ。チャレンジの無い方式は、
  フロー無しの 1 回の要求で完了できる（`LoginOnce`・`SecondFactorOnce`）。方式専用の登録の開始が返すフロー ID は、汎用の完了でも使える
- `/v1/me/methods` と管理 API の一覧は、TOTP とパスワードを今までどおり `totp`・`password` の欄に出し、汎用の `credentials` には
  載せない（同じものを 2 度数えないため）。1要素目の手段の数え方（最後の手段の判定）も変えない。パスワードはフィーチャーが止まって
  いても数える（今までどおり）

### 片付け

- フィーチャー `password` の無効化は、`authn_credentials` の方式 `password` と、古い表に残ったものを数えて消す
- 消去は両方の表を消す（今までどおり）。統合（0082）は、TOTP・パスワードが統合先にあれば統合元のものを無効化して残し、無ければ
  汎用の認証情報として（統合先のデータ鍵で暗号化し直して）移す

## 結果

- TOTP とパスワードの規則が `authn/method/totp`・`authn/method/password` に閉じ、方式専用のパスと汎用のパスが同じ処理で動く
- パスワードのハッシュを直列のトランザクションの外で計算する形を、ポートの側で持てた。ほかの重い方式（外部 Authenticator など）も
  同じ形で呼ぶ
- 移す前のバイナリには戻せない（台帳が拒む）。戻すには書き出したものを読み込む
- 移す間（ローリングの更新）は、移す前のサーバーを止める必要がある
- 古い表と、その Repository は次のリリースまで残る。passkey を移すまで、方式専用の表と汎用の表の両方を扱うコードが残る

### 追記（2026-11-02）：未公開のため移行を外した

このソフトウェアはまだ公開していないので、移す前のデータは無い。「移行」の節のうち、次を外した（「方式」「ポート」「セッション」
「HTTP」「片付け」の決定はそのまま）。

- 方式専用の表（`authn_totp_credentials`・`authn_password_credentials`）を消すマイグレーションを足した（SQLite 00060、PostgreSQL 00043）。
  Storage のポートとアダプタから `TOTPRepo`・`PasswordRepo` を消した
- 起動時の移行（`credential.MigrateLegacy`）と、台帳の `migration:` の記録の扱い（`feature.RegisterMigration`。移す前のバイナリの起動を
  拒む仕組み）を消した。マイグレーションは残っていた記録を消す。台帳はフィーチャーだけを記録する（0011、0073 のまま）
- 移した TOTP が保つはずだった `otp_`、パスワードの `pwd_` の ID の接頭辞と、その分岐（セッションの結び付き、運営者の無効化）を消した。
  TOTP とパスワードの ID は汎用の `crd_` だけ
- 古い暗号文の AAD（`totp.secret`）を消した

## 検討した代替案

- **SQL のマイグレーションで写す**：暗号文の AAD と形が違い、平文のハッシュも暗号化が要るので、SQL では写せない
- **方式専用の AAD のまま `authn_credentials` に置く（データの形のバージョンで区別）**：AAD が行に結び付かず、同じユーザーの別の行の
  暗号文に差し替えられる。コアが方式ごとに AAD を変える分岐も要る
- **読みを新しい表と古い表の両方にする（0092 の案）**：TOTP・パスワードを読む場所（セッションの検証、一覧、統合、復旧、無効化）の
  すべてに分岐が要り、起動で移し終えれば要らない
- **パスワードの照合をトランザクションの中で行う**：Storage のトランザクションが直列なので、ログインのたびにほかの書き込みが数十ミリ秒
  止まる。前の実装も外で計算していた
- **TOTP をフィーチャーにする**：既存の DB の台帳に無いので、設定で `features` を並べている環境では TOTP が止まる
- **パスワードの変更を同じ認証情報の置き換え（Update）にする**：変更の履歴（無効化した行。4.6）が残らない
