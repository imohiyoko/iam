# 0031. 通知は ID だけを渡し、文面・URL・配送は外部が行う

- 状態: 承認
- 日付: 2026-10-25
- 関連: [design.md](../design.md) 2.4
- 置き換え対象: [0009](0009-notifier-delegated.md)

## 背景

0009 では配送を外部に任せつつ、SMTP リレーのために IAM が既定のメールテンプレートを持っていた。しかし、文面やデザインはホスト先のブランドに属するもので、IAM が持つと二重管理になる。また、メール内のリンクのドメインを IAM が決めると、ホスト先がドメインを切り替えたいときに IAM の変更が必要になる。

## 決定

- IAM はメールの文面も URL も作らない。通知は ID と最小限のメタデータ（種類、realm、user、org、locale、期限）だけを Webhook で渡す
- 秘密の値（トークン）と宛先はペイロードに入れない。外部の配信の仕組みが、権限を持つサービスアカウントで、通知 ID から1回だけ取り出す（`:claim`）
- リンクはホスト先が自分のドメインで組み立て、トークンは公開 API で検証する
- SMTP リレーアダプタは廃止する。開発用アダプタは、設定した開発用の URL の形式でリンクを表示するだけにする

## 結果

- ホスト先はドメイン・文面・配送手段を自由に変えられる
- 秘密が Webhook の受け手のログや中継のシステムに残らない
- 本番でメールを送るには、IAM の外に配信の仕組みが必要になる（参考実装は別リポジトリとして用意してもよい）

## 検討した代替案

- IAM が既定テンプレートで SMTP に渡す（0009。文面とドメインを IAM が握ってしまう）
- トークンをペイロードに含める（受け手のログに秘密が残る）
