# 0032. ID とパスワードだけでログインできるアカウントを許可する

- 状態: 一部置き換え: 0035（2要素目の扱い）
- 日付: 2026-10-25
- 関連: [design.md](../design.md) 4.1

## 背景

passkey や OAuth が使えない環境があり、メールアドレスをログインの ID として使いたくない利用者もいる。

## 決定

- ID（ユーザー名）とパスワードだけでログインできるアカウントを作れるようにする。ただし、アカウントには確認済みのメールアドレスを1つ持たせる（0034）。フィーチャー（`password`、`username`）として提供し、realm の設定で有効にする
- ユーザー名は正規化（NFKC + 小文字化、紛らわしい文字の拒否）し、ブラインドインデックスで一意性を保証する
- パスワードは argon2id でハッシュ化する。最低長・漏洩済みパスワードの扱い・2段階認証の要否は、ホスト先と Org の設定で決める（0033）。既定値は NIST SP 800-63B に沿う
- リカバリーコードの発行、bot 対策（`pre_registration` フック）、レートリミットも設定項目とする
- 1要素の認証として警告の対象にする。拒否するかどうかは設定で決める

## 結果

- メールアドレスをログインに使わずに済む。復旧と通知は登録済みのメールアドレスで行える
- 登録時にユーザー名の存在が分かってしまう（隠せない）。レートリミットで緩和する

## 検討した代替案

- 検証なしのメールアドレスを ID として使う（他人のアドレスを名乗れてしまい、復旧や通知に使えない）
