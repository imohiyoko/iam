# 0032. ID とパスワードだけでのアカウント作成を許可する

- 状態: 承認
- 日付: 2026-10-25
- 関連: [design.md](../design.md) 4.1

## 背景

メールアドレスを持たない、または渡したくない利用者もいる。passkey や OAuth が使えない環境もある。

## 決定

- ID（ユーザー名）とパスワードだけでアカウントを作れるようにする。フィーチャー（`password`、`username`）として提供し、realm の設定で有効にする
- ユーザー名は正規化（NFKC + 小文字化、紛らわしい文字の拒否）し、ブラインドインデックスで一意性を保証する
- パスワードは argon2id でハッシュ化する。最低長・漏洩済みパスワードの扱い・2段階認証の要否は、ホスト先と Org の設定で決める（0033）。既定値は NIST SP 800-63B に沿う
- リカバリーコードの発行、bot 対策（`pre_registration` フック）、レートリミットも設定項目とし、既定値は安全側（発行する・求める）にする
- 1要素の認証として警告の対象にする。拒否するかどうかは設定で決める

## 結果

- メールなしで使える一方、復旧手段はリカバリーコードと運営者による復旧に限られる
- 登録時にユーザー名の存在が分かってしまう（隠せない）。レートリミットで緩和する
- bot 対策が「後回しでよいもの」から、このフィーチャーの既定の要件になった

## 検討した代替案

- メールアドレスを必須にする（メールを使いたくない利用者を排除する）
- 検証なしのメールアドレスを ID として使う（他人のアドレスを名乗れてしまい、復旧や通知に使えない）
