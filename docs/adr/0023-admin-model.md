# 0023. 管理権限は realm の運営者ロールと Org のロールの2層で表す

- 状態: 承認
- 日付: 2026-10-25
- 関連: [design.md](../design.md) 4.11

## 背景

運営者、セキュリティ担当、Org の管理者など、管理の主体が複数ある。管理のためだけの権限判定を別に作ると、認可の仕組みが二重になる。

## 決定

- 管理権限も authz のロールで表す。realm 範囲の運営者ロール（owner / admin / security / support / billing）と、Org 範囲のロール（owner / admin / member）
- 個人情報の復号は独立した権限（`pii:read`）にする
- 管理操作には強い認証と直近の認証を求める
- 常設の緊急用アカウントは作らず、Storage と KeyStore に直接アクセスできる CLI を緊急時の手段とする
- Org を作れる人は realm の設定で決める（既定は誰でも）

## 結果

- 認可の仕組みを1つに保てる
- 緊急時の CLI の利用は、重要度の高いイベントとして必ず通知される

## 検討した代替案

- 管理専用の権限判定（認可の仕組みが二重になる）
- 常設の緊急用アカウント（攻撃対象になる）
