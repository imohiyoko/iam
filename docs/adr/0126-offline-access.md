# 0126. offline_access は既定オフのフィーチャーにし、連携先ごとに許した認可だけをログアウトから切り離す

- 状態: 承認
- 日付: 2026-11-11
- 関連: [design.md](../design.md) 5.1、11.0、[0066](0066-oidc-authorization-code-flow.md)（一部置き換え）、[0099](0099-token-exchange.md)

## 背景

ADR 0066 は、リフレッシュトークンをログインの系列（セッション）に結び付け、ログアウト・セッションの期限で一緒に失効させた。
本人がブラウザにいない間も動くもの（メールやカレンダーの同期、バックアップ、モバイルのアプリ）は、ログアウトのたびに
つながり直しになる。OIDC Core 11 の `offline_access` は、これをはっきり求めた連携先にだけ、系列から切り離したリフレッシュトークンを出す。

## 決定

- フィーチャー `offline_access`（既定オフ）。連携先の登録に `offline_access`（真偽）を足し、フィーチャーが動いているときだけ置ける（オフなら `400`）
- フィーチャーが動いていて、連携先に許していて、`offline_access` のスコープを求めたときだけ、認可を Offline にする（Discovery の
  `scopes_supported` に出す）。それ以外ではスコープから `offline_access` を外したふつうの認可にする（OIDC Core 11 の「無視する」）。
  運営者が連携先に許したことを OIDC Core 11 の「ほかの条件」とし、同意の画面は出さない（サードパーティの連携先は扱わない）
- Offline の認可は、ログアウトと系列の続きへの入れ替え（ローテーション・ログインのやり直し・Org の切り替え）では失効させない。
  ほかの理由で系列が終わったとき（本人・運営者による失効、停止、有効期間、認証情報の変更、復旧）は一緒に失効させる。
  セッションをまとめて失効させたとき（認証情報の変更・復旧・運営者による失効など）は、ログアウト済みの系列の Offline の認可も、
  残したセッションの系列のものを除いて失効させる（パスワードはセッションをメールに結び付けるので、認証情報の ID では追えない）
- セッションの代わりに、使うたびに次を確かめる：フィーチャーが動いている、連携先がまだ許している、ユーザーがいて削除の予定が無い、
  停止・有効期間（認可の後に始まった停止は解除しても戻さない）、認可に使った認証情報が使える（認可に保存する。セッションと違い、ログインに使ったメールを本人から外していないかも確かめる）、Org の所属
- 認可コードを出した後に系列で本人確認をやり直していれば、Offline の認可には交換しない（今のセッションの認証情報はコードのものではない）。
  Offline の認可から交換した認可（ADR 0099）も、元の認可が Offline として使えること（連携先の許可・認証情報など）を確かめる
- 寿命は `oidc.offline_idle_ttl`（無操作の期限。既定 30 日、使うたびに延びる。ローテーションしない FAPI 2.0 の連携先は同じトークンの期限を延ばす）と `oidc.offline_max_ttl`（認可の寿命。既定 365 日、延びない）
- 本人は `GET /v1/me/offline-access` で連携先ごとに見て、`POST /v1/me/offline-access/{client_id}:revoke` で取り消せる
  （監査ログ `oidc.grant_revoked`、理由 `revoked_by_user`）
- 無効化（片付け）では、連携先の `offline_access` を外し、Offline の認可とそのトークンを消す。オフの間に残った Offline の認可は使えない（fail-closed）
- Token Exchange（ADR 0099）で交換したトークンは、交換元が Offline でも系列に結び付いたまま（Offline にしない）

## 結果

- 本人がいない間に動く連携先が、ログアウトの後も使い続けられる
- ログアウトしても消えない認可ができる。本人の一覧と取り消し、無操作の期限、認可の寿命、停止・認証情報の変更での失効で抑える
- 認可の行に、認可に使った認証情報の ID を持つ

## 検討した代替案

- 同意の画面を出す：連携先はすべて運営者が登録するファーストパーティで、許すかは連携先ごとに運営者が決める
- ログアウトでも Offline の認可を失効させる：`offline_access` を求める意味が無くなる
- 期限を設けない：使われなくなった認可が残り続ける
