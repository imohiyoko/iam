# 0072. 保持期間は1つの掃除のループで消し、監査ログはチェックポイントを残して先頭から切り詰める

- 状態: 承認
- 日付: 2026-10-27
- 関連: [design.md](../design.md) 6.5、9.6、[0063](0063-audit-client-data.md)、[0071](0071-siem-outputs.md)

## 背景

監査ログはホスト先の保持期間（既定90日）を過ぎたら消し、長期保管は SIEM に任せる（6.5）。失効したセッションや配送済みの
outbox なども期間の後に消す（9.6）。メールは realm で、暗号文を持たない最小化モード（`index_only`）を選べる（9.6）。

## 決定

- `eventlog.Retention` が1時間ごとに掃除する（`outbox.batch` 件ずつのトランザクション）。設定は `realm.audit_retention`
  （既定 90d）、`realm.ended_retention`（既定 7d）、`realm.email_storage`（`encrypted` / `index_only`）。0 は消さない
- 監査ログ：先頭から、時刻が期間より前のレコードを消す（時刻が期間内のレコードに当たったら止め、時刻の逆転があっても新しいものは消さない）。
  最新のレコードは消さない（`Last` からチェーンを続けるため）。最後に消したレコードの seq とハッシュを
  チェックポイント（`shared_audit_checkpoint`。1行）に置き、同じトランザクションで `audit.truncated`（`through_seq`、
  `through_hash`、`removed`、`before`）を記録する。この出来事は outbox を通って SIEM に届く
- 検証（`eventlog.Verify`、`iam storage import`）はチェックポイントの次から、チェックポイントのハッシュを前のハッシュとして始める
- セッションは期限（`expires_at`）か失効の時刻が期間より前なら消す。outbox は配送の時刻、予約イベントは発火の時刻で消す。
  未配送・未発火のものは消さない
- `index_only`：メールを作るときに暗号文を作らない。切り替えた後の掃除で、残っている暗号文を消す（インデックスは残す）。
  アドレスの表示、ID トークンの `email`、Org の管理者に見せるメールは出さない。操作起点でない通知（復旧の完了）は、
  宛先なしの通知を1件出し、外部が `user_id` から宛先を解決する

## 理由

- チェックポイントは1行で足りる。SIEM は `audit.truncated` のハッシュと、受け取った最後のレコードのハッシュを照らし合わせれば、
  切り詰めが正しい位置だったことを確かめられる
- 最新のレコードを残せば、Repository の `Last` と `Append` は変えずに済む
- 掃除を1つのループにまとめれば、間隔と件数の調整が1か所になる

## 影響

- 監査ログの seq は 1 から始まるとは限らない。件数ではなく最後の seq を見る
- 無効化した認証情報の削除（9.6）は、認証手段ごとの Repository に削除を足す必要があり、後に回す
- `index_only` からは `encrypted` に戻せない（消えたアドレスは戻らない）。戻した後に作るメールから暗号文を持つ

## 検討した代替案

- 監査ログを日ごとのパーティションで消す：SQLite で使えず、アダプタごとに仕組みが分かれる
- チェックポイントを監査ログのレコードとしてだけ残す：検証の開始点を探すのに走査が要る
