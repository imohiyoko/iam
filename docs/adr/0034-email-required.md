# 0034. すべてのユーザーに確認済みのメールアドレスを1つ以上持たせる

- 状態: 承認
- 日付: 2026-10-25
- 関連: [design.md](../design.md) 4.1, 4.3

## 背景

passkey のみ、ID とパスワードのみで登録できるようにすると、メールアドレスを持たないアカウントが生まれる。その場合、アカウント復旧の手段がリカバリーコードと運営者による復旧に限られ、停止や削除の予定などの重要な通知も本人に届けられない。

## 決定

- すべてのユーザーは、確認済みのメールアドレスを1つ以上持つ。ログインに使う手段とは独立した必須項目とする
- アカウントはメールの所有確認が完了した時点で作成する
- OAuth / SSO のプロバイダが確認済みとしたメールは、realm の設定で確認済みとして受け入れられる
- 最後の確認済みメールアドレスは削除できない
- サービスアカウントは対象外
- メールを送れない環境のために、メールを送らずに確認済みとみなす経路（OAuth プロバイダ、SSO、招待、運営者による登録）を用意し、どれを有効にするかは realm で選ぶ（design.md 4.1）

## 結果

- すべてのアカウントで、メールによる復旧と重要な通知が使える
- メールでの確認コードを使う場合は、外部の配信の仕組みが必要になる。使えない環境では、OAuth と運営者による登録で運用し、メールによる復旧は使えない
- 最小化モード（ブラインドインデックスのみ）でもこの条件は満たせる

## 検討した代替案

- メールアドレスを任意にする（復旧と通知の手段を確保できないアカウントが生まれる）
