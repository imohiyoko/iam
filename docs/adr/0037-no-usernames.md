# 0037. ユーザー名（独自の ID）は持たず、パスワードはメールアドレスと組み合わせる

- 状態: 承認
- 日付: 2026-10-25
- 関連: [design.md](../design.md) 4.1
- 置き換え対象: [0032](0032-username-password-signup.md), [0035](0035-id-login-requires-second-factor.md)

## 背景

0032 で ID（ユーザー名）とパスワードでのログインを許可し、0035 で2要素目を必須にした。しかしユーザー名は、正規化の扱い次第で一意性を確実に保証しにくい。また登録時に「この ID は登録済みです」と返さざるを得ず、ID の存在を隠せない。

## 決定

- ユーザーが自由に決める ID（ユーザー名）は登録できないようにする。ログインの識別子はメールアドレス、passkey、OAuth / SSO の外部 ID のみ
- パスワードは、メールアドレスと組み合わせたログイン手段としてフィーチャーで提供する。要件と2段階認証の要否は設定で決める（0033）
- 表示名やハンドルが必要なら、ホスト先のアプリが持つ

## 結果

- 識別子の一意性は、メールアドレスの正規化（小文字化のみ）とブラインドインデックスで保証できる
- 登録済みかどうかを画面で区別せず、通知で伝えられる（0022）
- 0035 の「2要素目を設定で外せない」という例外は不要になり、パスワードの厳しさは他の項目と同じく設定で決める
- メールアドレスによる列挙のリスクは、0022 の開示のルールとレートリミットで扱う（当面これで十分とする）

## 検討した代替案

- ユーザー名を許し、2要素目を必須にする（0035。存在を隠せない問題は残る）
