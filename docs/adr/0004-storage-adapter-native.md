# 0004. Storage アダプタは DB ごとに内部を最適化する

- 状態: 承認
- 日付: 2026-10-25
- 関連: [design.md](../design.md) 2.4, 12

## 背景

複数の DB に対応する場合、全 DB で同じ SQL を書く（最小公倍数）と、各 DB の得意な機能を使えず性能が落ちる。

## 決定

- Repository はドメインの言葉（何をしたいか）で定義する
- 各アダプタは、その DB の得意な機能（JSONB、RETURNING、ltree など）を自由に使って実装する。スキーマも DB ごとに違ってよい
- DB 固有の追加機能（LISTEN/NOTIFY 等）はオプションのポートにし、無ければ代替手段に切り替える
- 振る舞いの一致は、全アダプタ共通の契約テストで保証する

## 結果

- DB ごとに最適な性能が出せる
- アダプタごとの実装量は増える。契約テストの充実が前提になる

## 検討した代替案

- 全 DB 共通の SQL のみを使う（性能と表現力を犠牲にする）
