# 0025. アカウント復旧は複数の経路と復旧専用のセッションで行う

- 状態: 承認
- 日付: 2026-10-25
- 関連: [design.md](../design.md) 4.12

## 背景

管理者が全認証情報を無効化できるため、認証手段を失ったユーザーが戻る手段が必要。メールによる復旧は、メールアカウントが乗っ取られると突破される。

## 決定

- 経路はリカバリーコード、検証済みメール、Org 管理者による復旧、運営者による復旧の4つ。realm で有効にする経路を選び、Org が弱い経路を禁止できる
- 本人確認後は、新しい認証手段の登録しかできない復旧専用のセッションを発行する
- メールによる復旧には、待機期間・全連絡先への通知・警告を組み合わせる

## 結果

- 復旧手段の強さを Org の要件に合わせられる
- 運営者による復旧では、IAM の外での本人確認が必要

## 検討した代替案

- メールのみ（弱い）
