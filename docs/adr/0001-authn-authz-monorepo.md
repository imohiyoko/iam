# 0001. 認証と認可を同一リポジトリの別モジュールにする

- 状態: 承認
- 日付: 2026-10-25
- 関連: [design.md](../design.md) 2.1, 2.2

## 背景

個人で開発するため、リポジトリを分けると運用コストが増える。一方で、境界が曖昧になると独自仕様化（ガラパゴス化）し、後から分離できなくなる。

## 決定

- 認証（authn）と認可（authz）は同一リポジトリに置き、別モジュールとして実装する
- authz が authn から受け取るのは principal の ID と Org の ID だけにする
- DB でもモジュールをまたぐ JOIN・外部キーを禁止し、ID でのみ参照する
- Org は認証側（テナント境界）、Group・Role は認可側の概念とする

## 結果

- 必要になった時点でサービスとして切り出せる
- 境界のルールはレビューと静的検査で守る必要がある

## 検討した代替案

- リポジトリを分ける（運用コストに見合わない）
- 境界を決めずに1モジュールにする（後から分離できない）
