# 0051. メール + パスワード（フィーチャー password）の細部

- 状態: 承認
- 日付: 2026-10-26
- 関連: [design.md](../design.md) 2.4、4.1、4.3、4.9、5.2、9.2、10章、11.0、[0050](0050-second-factor.md)

## 背景

M2 でメール + パスワードをフィーチャー `password`（既定オフ）として作るにあたり、design.md に書かれていない細部を決める必要があった。

## 決定

### 設定と照合

- ハッシュは argon2id の PHC 文字列。既定は m=64MiB、t=2、p=1（`security.password.argon2`）。本番では OWASP の下限（m=19MiB、t=2）より
  軽くできない。パラメータを変えると、ログインの成功時に作り直す
- 入力は NFKC で正規化してから数え、ハッシュにする。最低長は 15 文字（`security.second_factor.required` なら 8 文字）、上限は 128 文字。
  文字種の組み合わせは強制しない（NIST SP 800-63B）
- 有効なパスワードはユーザーに1つ。変更・削除は無効化で表し、新しい行を作る
- 設定はログイン済みの本人だけ。変更・削除には今のパスワードが要り、初めての設定には直近の認証（`max_auth_age`）が要る
  （盗まれたセッションで、持ち主の知らないパスワードを足させない）
- 変更・削除の後は、そのセッションの他のセッションを一括で失効させる（5.2）。パスワードは他の認証情報と違い、セッションの
  認証情報の ID には入れない（変更した本人のセッションを残すため）
- パスワードはログインの手段に数える（最後の手段なら外せない。4.3）。メール + パスワードでのログインには確認済みのメールが要る

### ログイン

- 失敗の理由（アカウントの有無、メールの未確認、ユーザーの停止、パスワードの違い）は返さない。アカウントが無いときも同じ重さの
  照合をしてから失敗し、応答時間の下限（4.9）と合わせて有無を読ませない
- 回数はアドレスごと（`security.login.rate_limit.per_account`）と接続元ごとに制限する
- `amr` は `pwd`。2段階認証は他の1要素目と同じ（0050）。パスワードだけのログインは警告 `single_factor` の対象

### 漏洩済みパスワード

- 新しいポート `BreachChecker` で確かめる。渡すのは SHA-1 だけで、アダプタ `hibp`（既定）は Pwned Passwords の range API に
  先頭 5 文字だけを送り、詰め物（Add-Padding）を求める（k-匿名）。`breach_check.driver` を空にすると確かめない
- 設定・変更では拒否し（`400 password_breached`）、ログインでは警告 `password_breached`（high、既定 warn）にする
- 外部の障害では確認を飛ばし、ログに残す（ログインと設定を止めない）。タイムアウトは既定 2 秒

### 今回は作らないもの

- パスワードでの新規登録（今はメールのコードか OAuth で登録してから設定する）と、メールによるパスワードの再設定は、アカウントの
  復旧（4.12、#35）と一緒に作る

## 結果

- 外部への送信はパスワードを推測できない形（SHA-1 の先頭 5 文字）に限られる。送りたくない環境では driver を空にする
- パスワードの変更で他の端末のセッションが切れる
