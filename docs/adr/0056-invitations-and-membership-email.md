# 0056. 招待と Membership ごとのメール

- 状態: 承認
- 日付: 2026-10-26
- 関連: [design.md](../design.md) 3.1、4.1、4.4、9.5、[0055](0055-org-foundation.md)

## 背景

M3 で共有 Org にメンバーを招く（4.4）。design.md は「招待したアドレスが Membership に結び付く（受け入れに所有確認が必要）」
「Org とその文脈に見えるのは結び付けたメールだけ」「結び付いたメールは消せない（`email_bound_to_membership`）」を決めているが、
所有確認の方法、まだユーザーでない人の登録、アドレスの暗号化の鍵、権限を決める必要があった。

## 決定

- 招待できるのは Org の `owner` と `admin`（`org:invite`）。`owner` として招けるのは `owner` だけ。個人 Org には招待できない
  （`personal_org`）。既に active なメンバーのアドレスは `already_member`
- 招待はトークン（`<招待の公開 ID>.<32 バイトの乱数>`、ハッシュだけを保存）を通知 `org_invitation` で招待したアドレスに送る。
  宛先とトークンは配信用のサービスアカウントが claim で取り出す（ADR 0031 と同じ）。有効期限は既定 7 日
- アドレスは招待ごとのデータ鍵（ID は招待の内部 ID）で暗号化し、受け入れ・取り消しで鍵を消す。終わった招待のアドレスは
  一覧にも返さない。期限切れの pending の招待の鍵は、#52 の片付けの処理で消す
- 受け入れ（`POST /v1/invitations:accept`）。トークンは招待したアドレスに届くため、realm が確認の経路 `invitation` を
  受け入れる（4.1。既定は無効）ときは、トークンがそのアドレスの所有確認を兼ねる
  - ログインしていて、アドレスが本人のもの：そのメールを結び付ける
  - アドレスが誰のものでもない：`invitation` が有効なら本人に確認済みのメールとして足して結び付ける（ログインしていなければ、
    そのアドレスで登録し、招待された Org に入ったセッションを返す）。無効なら `email_verification_required`
    （本人が先にコードでアドレスを確かめてから受け入れる）
  - アドレスがほかのユーザーのもの：ログインしていれば `email_exists`、いなければ `login_required`（トークンでのログインはしない）
- 受け入れは原子的（pending の招待を1つだけ閉じる）。終わった Membership があれば使い直す（UNIQUE (user, org)。再参加は新しい招待で）
- 本人は Membership に結び付けるメールを確認済みの自分のメールに切り替えられる（`:bind-email`。省けば primary）。
  ドメインの制限・切り替えの禁止は Org のポリシー（#53 以降）で足す
- Org のメンバーの一覧（owner と admin）は、メンバーごとに結び付けたメール（未設定なら primary）だけを返す
- 結び付けたメールは `email_bound_to_membership` で消せない（終わった Membership は数えない）

## 結果

- 招待のアドレスが、ユーザーにならないまま平文で残ることはない
- 経路 `invitation` を無効にした realm（既定）でも、本人が先にアドレスを確かめれば招待を受け入れられる
- トークンだけで既存のユーザーとしてログインはできないため、招待のメールが漏れても既存のアカウントは乗っ取られない

## 検討した代替案

- 招待のアドレスを Org の鍵で暗号化：Org に鍵を持たせる仕組みが増え、招待が終わっても消せない
- トークンで既存のユーザーをログインさせる：マジックリンクと同じ強さになるが、realm が `code` を無効にしている場合に
  ログインの経路が増えてしまう
