# 0033. どこまで厳しくするかは、ホスト先と Org の設定で決める

- 状態: 承認
- 日付: 2026-10-25
- 関連: [design.md](../design.md) 2.8

## 背景

パスワードの要件、2段階認証の要否、bot 対策、復旧の経路、セッションの寿命、警告のアクションなど、セキュリティの強さに関わる項目が増えた。適切な厳しさはホスト先の用途や Org の要件によって違い、IAM が1つに決めると、緩すぎるか厳しすぎるかのどちらかになる。

## 決定

- セキュリティの強さに関わる項目は、ホスト先 → realm → Org の階層で設定する
- ホスト先が既定値と設定できる範囲を決め、項目ごとに Org が緩められるかも決める（既定は厳しくする方向のみ）
- IAM は安全側の既定値を用意する
- IAM の安全性の前提になっている不変条件（13.5）は、設定で外せない

## 結果

- 用途に合わせた厳しさを選べる
- 設定の組み合わせが増えるため、実際に効いている値を確認できる API・CLI が必要になる
- 0007（警告）、0027（セッションの寿命）など、個別に決めていた階層設定をこの仕組みに統一する

## 検討した代替案

- IAM が厳しさを固定する（用途に合わない）
- Org が自由に緩められる（ホスト先が全体の安全性を保てない）
