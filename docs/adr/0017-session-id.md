# 0017. セッションは公開用の ID と秘密のトークンに分ける

- 状態: 承認
- 日付: 2026-10-25
- 関連: [design.md](../design.md) 5.2

## 背景

セッションをログや SIEM で相関させたいが、トークンそのものをログに出すと漏洩につながる。

## 決定

- 公開用のセッション ID（`ses_...`）と、256bit の秘密のトークンを分ける。トークンは `<ID>.<秘密>` の形にし、DB には秘密部分のハッシュのみを保存する
- ログ・イベント・`sid` クレームには公開用の ID だけを使う
- Cookie は `__Host-`、Secure、HttpOnly、SameSite=Lax
- ログイン・権限の変更・一定時間ごとに ID を入れ替える（セッション固定攻撃の対策）

## 結果

- ログの相関と秘密の保護を両立できる

## 検討した代替案

- トークンをそのまま ID として使う
