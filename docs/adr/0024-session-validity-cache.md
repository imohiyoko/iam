# 0024. セッションの有効性をキャッシュし、反映遅れの上限を保証値とする

- 状態: 承認
- 日付: 2026-10-25
- 関連: [design.md](../design.md) 5.3

## 背景

セッションの検証で、停止・有効期間・認証情報の無効化・Org の状態をすべて確認する必要があり、毎回 DB に問い合わせると遅い。

## 決定

- 検証結果を「セッションの有効性」としてまとめてキャッシュする
- 変更時の即時削除（ベストエフォート）に加え、TTL を必ず付ける
- 変更が反映されるまでの遅れの上限（既定30秒）を公開仕様の保証値とする
- 次に状態が変わる時刻もキャッシュに持たせる

## 結果

- ホットパスを軽く保てる
- 上限の範囲内では、古い状態で判定されうる

## 検討した代替案

- 毎回 DB に問い合わせる（遅い）
- TTL なしのキャッシュ（無効化の取りこぼしで古い状態が残り続ける）
