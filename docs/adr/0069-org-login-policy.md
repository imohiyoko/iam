# 0069. Org のログインポリシーは Org の設定に持ち、ログインと切り替えのときに判定する

- 状態: 承認
- 日付: 2026-10-27
- 関連: [design.md](../design.md) 4.4、4.9、11.12、[0062](0062-org-tier-settings.md)

## 背景

Org ごとに「passkey でなければ入れない」「会社のメールの Membership だけ」「社内の IP からだけ」のような入場の条件を
置きたい（フィーチャー `org_login_policy`、roadmap M6）。design.md 3章は `org_login_policies` の表を置いていた。

## 決定

- ポリシーは Org の段の設定（0062、`orgs.settings` の JSON）の `login_policy` に持つ。表は作らない
- 種類は3つ。空の項目は判定しない
  - `require_passkey`：その認証の amr に `hwk` があること
  - `membership_email_domains`：Membership に結び付けたメール（無ければ primary）が確認済みで、ドメインがどれかであること。
    ドメインはメールのドメインのブラインドインデックス（メールと同じインデックス鍵）で比べ、復号しない
  - `ip_allowlist`：ログイン・切り替えの要求の IP が CIDR のどれかに入ること
- 判定はログイン（Org の決定）と Org の切り替えのとき。満たさない Org は候補から外し、ログインは個人 Org などで成功する。
  明示的に指定した Org（切り替え）なら 403 で、理由は `policy.<種類>`。2要素目の前の段では判定せず、完了のときに判定する（満たさなければ、その段で決めた Org ではなく他の Org に入る）
- 既存のセッションには遡って当てはめない（入場の条件。停止や有効期間とは違う）
- 招待からの登録で、招待された Org のポリシーを満たさなければ（メールのコードで登録したので passkey が無いなど）、
  参加は済ませ、セッションは個人 Org に入る
- 設定にはフィーチャー `org_login_policy`（`org` に依存、既定はオフ）が要る。オフにすると判定しない（設定は残る）。
  オフの間は新しいポリシー・変えたポリシーを受けないが、保存済みのポリシーをそのまま残す更新や外す更新は受ける
- 個人 Org には置けない（Org の段の設定と同じ）。ドメインは50件、CIDR は100件まで。保存のときに正規化する
  （ドメインは小文字、CIDR はマスクした形で IPv4-mapped は IPv4 に直す、重複を除く）

## 理由

- 設定の変更・監査・取得の口（0062）をそのまま使える。ポリシーは Org ごとに小さく、検索の要が無い
- 判定に要る材料（amr・IP・Membership のメール）はログインの時点でそろう

## 影響

- `require_sso` などの種類は、SSO（M7 以降）で足す
- design.md 3章の `org_login_policies` は Org の設定に含めたことを注記する

## 検討した代替案

- 表 `org_login_policies` を作る：種類ごとの行に分けても判定は全部を読むので利点が無く、マイグレーションと書き出しが増える
- 既存のセッションにも当てはめる：IP は要求ごとに変わり、セッションの検証のたびに判定するのは重い。入場の条件として扱う
