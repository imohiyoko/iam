# 0019. Org の人数上限は Membership の前提条件として扱う

- 状態: 承認
- 日付: 2026-10-25
- 関連: [design.md](../design.md) 4.9, 11.14

## 背景

人数の上限は、外部のプラン、追加購入の足し算、期間限定の増減などで決まる。時刻を指定した招待で枠が足りない場合の挙動も決める必要がある。

## 決定

- 上限は期間つきの付与（base / addon / override）の合算で求める。外部の課金システムからは external_ref で冪等に登録する
- 上限は Org の Membership の前提条件として、追加・招待のときに判定する。足りなければエラーで拒否し、待機列は持たない
- 新しいメンバーの有効期間のすべての時点で上限を満たすかを確認する（期間が重ならない人同士は枠を共有できる）
- 上限を下回っても既存のメンバーは外さず、新規追加を止めてイベントを出す

## 結果

- 結果が予測しやすい
- ホットパスには影響しない

## 検討した代替案

- 枠が空いたら自動で有効にする待機列（結果が予測しにくい）
