# 0011. ビルド時にフィーチャーを選択し、台帳で構成変更を保証する

- 状態: 承認
- 日付: 2026-10-25
- 関連: [design.md](../design.md) 11.11, 11.12

## 背景

起動時のオン・オフだけでは、使わないコードや依存がバイナリに残り、攻撃面と依存が増える。一方、ビルド構成を変えると、DB に残ったデータを新しいバイナリが扱えない事故が起こりうる。

## 決定

- `build.yaml` に列挙したフィーチャー・アダプタのパッケージだけを import してビルドする（自己登録方式。build tag は使わない）
- 公式イメージは「全部入り」と「最小構成」。それ以外は利用者がビルドする
- DB にフィーチャー台帳を持ち、バイナリに埋め込んだ構成と起動時に突き合わせる。扱えないデータがあれば起動を拒否し、判定は拒否側に倒す（fail-closed）
- 追加はバイナリ配布 → 有効化、削除は無効化（データの片付け）→ バイナリ配布、の順に行う。`iam features plan` で事前に差分を確認する

## 結果

- 攻撃面・依存・サイズを減らせる（レイテンシへの効果は小さい）
- 構成変更の手順が増える
- CI は全部入り・最小構成・最小構成 + 各フィーチャー1つずつ、に絞る

## 検討した代替案

- build tag 方式（管理しにくい）
- 起動時の切り替えのみ（攻撃面が減らない）
