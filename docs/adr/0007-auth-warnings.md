# 0007. 全認証経路に共通の警告の仕組みを持つ

- 状態: 承認
- 日付: 2026-10-25
- 関連: [design.md](../design.md) 10

## 背景

弱い暗号方式の passkey、耐量子でない TLS、未検証のメールなど、認証は成功させつつ注意を促したい場面が経路ごとにある。経路ごとに作ると重複し、抜け漏れが出る。

## 決定

- 各認証経路は、どう認証されたかを共通の Evidence として返す
- 経路を知らないルールが Evidence から警告コードを出す
- 警告ごとに ignore / warn / deny を、サーバー全体と Org で設定する。Org の上書きは厳しくする方向のみ

## 結果

- 新しい認証経路を足しても、既存のルールがそのまま効く
- 警告は監査ログに残り、RP には API で提供する（トークンには載せない）

## 検討した代替案

- 経路ごとに個別の警告を実装する
